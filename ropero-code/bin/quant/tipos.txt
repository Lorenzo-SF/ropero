# Los tipos de quant de llama.cpp: numero de llama_ftype <-> nombre.
#
# numero nombre
#
# Es la lista de RESPALDO: la fuente de verdad es el motor instalado
# (llama-quantize --help), que la lista de aqui solo sustituye cuando no
# esta. Son los tipos del enum llama_ftype de llama.cpp
# (include/llama.h), con sus numeros exactos.
#
# ── POR QUÉ llama_ftype Y NO ggml_type ──────────────────────────────────────
#
# El GGUF lleva el quant en "general.file_type", y ese numero es del enum
# llama_ftype (el de los ficheros: "Q4_K_M" = 15). El ggml_type es OTRO
# enum (el de los tensores sueltos: "Q4_K" = 12, "NVFP4" = 40). Son
# numeros parecidos y distintos, y confundirlos hace que un GGUF en NVFP4
# (39) se llame "MXFP4" (39 en ggml_type, que no existe: 39 ahi es MXFP4).
#
# Todo lo que lee esta lista lee el general.file_type, o sea llama_ftype:
# el model card, el nombre del repo al subirlo, y la verificacion.
#
# ── EL ORDEN DE LOS ALIAS ───────────────────────────────────────────────────
#
# El motor imprime "Q4_K" (alias de Q4_K_M) y "Q4_K_M" con el MISMO
# numero. El que manda es el canonico, asi que el canonico va PRIMERO: al
# buscar el nombre de un numero se coje el primero que aparece, y ese tiene
# que ser el bueno.
#
# La leen los dos: quant/quant-tipos.sh (bash) y quant/model-card.py
# (python). Si la cambias, cambiala aqui y en ningun otro sitio.
