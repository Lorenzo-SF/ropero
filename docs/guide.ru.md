# Руководство пользователя Ropero

[English](guide.en.md) · [Español](guide.es.md) · [Português](guide.pt.md) · [Français](guide.fr.md) · [Deutsch](guide.de.md) · [Italiano](guide.it.md) · [日本語](guide.ja.md) · [简体中文](guide.zh-CN.md) · [한국어](guide.ko.md) · **Русский**

Ropero — CLI на Rust для установки, настройки и запуска локальных ИИ-моделей с разными движками. Он подготавливает выбранный движок, запускает и контролирует его сервис, а при поддержке движка предоставляет API, совместимый с OpenAI. Ropero v2 находится в разработке.

## Начало работы

Соберите CLI из корня репозитория и посмотрите доступные команды:

```bash
cargo build --locked --release -p ropero-cli
ropero --help
ropero doctor
ropero install engines
```

Команда engines показывает доступные движки; можно указать нужный напрямую, например `ropero install engines basalt`. Установка движка подготавливает среду выполнения и зависимости. Модель устанавливается отдельно командой `ropero install models <model>`.

По умолчанию CLI работает на английском. Сохраните испанский командой `ropero config --lang ES`; команда `ropero config --lang EN` вернёт английский.

## Каталог и TOML

Манифесты в `engines/` описывают требования, обнаружение, установку и возможности движков. Файлы в `models/<engine>/` задают модель, формат, загрузку, артефакты и параметры запуска. При обычном использовании активные описания моделей находятся в `~/.config/ropero/models/<engine>/`, а пользовательские манифесты движков — в `~/.config/ropero/engines/`. TOML в репозитории служат примерами и автоматически не загружаются.

```bash
ropero models add
ropero models add --path model.toml
ropero install models <model>
ropero <model>
ropero status --live
```

## Движки и ограничения

- **llama-server** и **turbo-llama** запускают модели GGUF.
- **FastFlowLM** передаёт операции CLI `flm`; форматы и поддержка NPU зависят от FastFlowLM и XRT.
- **Ignis** использует загруженные артефакты движка.
- **Basalt** запускает пакеты `.basalt`. В Ropero он поддерживается только на Linux x86-64. После успешной установки движка Ropero добавляет TOML Qwen3.8-Flash-Next в каталог пользователя, если файла ещё нет; пакет модели устанавливается отдельно. Требуются CPU с AVX2, NVIDIA Blackwell и совместимый драйвер.
- **Strata** запускает подготовленные профили; Ropero не создаёт и не загружает их.
- Для **vLLM**, **MLX-Serve** и **TensorRT-LLM** есть адаптеры, но совместимость зависит от платформы и модели. Для MLX-Serve нужны macOS и Apple Silicon.
- Поддержка **AirLLM** частичная; серверного адаптера Ropero нет.

Требования и известные ограничения описаны в [подробном справочнике совместимости движков на английском](engine-support.en.md).

## Агенты, IDE и инструменты

Команда `ropero connect --list` показывает автоматические подключения, в том числе OpenCode, Codex, Claude Code, Pi, Hermes, OpenClaw, PicoClaw и VS Code. Сначала запустите модель в Ropero. Подключение настраивает клиент, но не устанавливает агента и не запускает движок.

Zed поддерживает совместимые с OpenAI конечные точки и хранит ключи в системном хранилище; настройте его через Agent Settings. Официальная документация Cursor не подтверждает прямое подключение к локальным точкам Ropero. MicroClaw принимает `llm_base_url` в конфигурации. Graphify — дополнительный инструмент анализа репозитория с совместимым помощником, а не движок или модель Ropero.

См. [справочник интеграций на английском](agent-integrations.en.md) и [справочник CLI на английском](especificacion/ropero-cli.en.md).

## Включение и отключение моделей

`ropero models` по умолчанию показывает установленные движки и готовые к использованию модели. Установленный движок без доступных моделей также отображается с пояснением. Используйте `--all` для просмотра всего каталога, а `--fired` — для отключённых моделей. Отключение и повторное включение перемещает TOML в каталог `fired/` движка или обратно; описание и файлы модели не удаляются. Если имя уже занято активной моделью, перед повторным включением Ropero запросит новое уникальное имя.

```bash
ropero models
ropero models --all
ropero models --fired
ropero model <modelo> --fired
ropero model <modelo> --hired
```
